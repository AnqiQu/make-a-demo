# Require a Demo Run Command

MakeADemo v1 requires submitted projects to expose a dedicated demo run command, such as `npm run demo`, that starts the app in a deterministic demo mode without runtime network access, secrets, external APIs, external databases, OAuth, paid services, or manual setup. Submitted repos must include a deliberately tiny `makeademo.config.json` as the source of truth for validation, with only `demoCommand` and `url` required. Dependency installation may use the network, but after dependency installation the demo sandbox must be isolated: any inbound or outbound network communication across the sandbox boundary is a hard validation failure for demo runtime and capture. We chose this over trying to infer and repair arbitrary project setup because reliable repo execution is central to the product, and pushing demo-readiness into an explicit contract gives makers a clear way to make their projects capturable. The user flow should present a preparation prompt before repo submission, then collect the repo URL and key product features to demo before validation begins.

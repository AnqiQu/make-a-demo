# Validate Repo Runnability Before Script Generation

MakeADemo should validate repo runnability before generating the Video Script, Capture Scripts, raw Scenes, or composed output. Validation clones a submitted repo, installs dependencies with network access allowed, then isolates the sandbox and treats any inbound or outbound network communication across the sandbox boundary as a hard failure while running the demo command and opening the resulting app in a browser. Playwright should run inside the isolated sandbox rather than from the backend host, so browser automation does not require network communication into the sandbox and artifacts can be copied out only after the run completes. We chose this ordering because every later stage depends on reliable browser access to the app, and validation exposes the real failure modes needed to refine the demo run contract and preparation prompt.

Validation must be programmatic and must not use LLM API calls. We chose this because runnability checks should be deterministic, cheap, and repeatable; LLM calls belong in later script generation, not in the gate that decides whether the repo is usable.

Dependency installation should be inferred from standard lockfiles rather than configured in `makeademo.config.json`: `bun.lock` or `bun.lockb` uses `bun install`, `pnpm-lock.yaml` uses `pnpm install --frozen-lockfile`, `yarn.lock` uses `yarn install --frozen-lockfile`, `package-lock.json` uses `npm ci`, and a repo with only `package.json` falls back to `npm install` with a validation warning that the install may be less deterministic. We chose this to keep the MakeADemo Config small while still supporting common JavaScript project layouts without making lockfiles a hard V1 requirement.
